# Feature workflow

1. Understand the request, repository rules (`engineering.md`), and affected modules.
2. Clarify essential unknowns (`ask`) only if ambiguity affects architecture, data, security, or public APIs.
3. Plan proportionally to risk (`plan`, using `implementation-plan.md` for non-trivial changes).
4. Implement focused changes (`implement`) within approved scope.
5. Verify behavior (`test`) and review the diff (`review`).
6. Report modified files, actual check results, and limitations (`completion-report.md`).
